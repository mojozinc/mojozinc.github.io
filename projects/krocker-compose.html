krocker-compose

Developer Tooling • Production CLI
Domain: Local Developer Tooling & Container Orchestration
Stack: Python, Docker, docker-compose, Bash
Context: TiVo / Xperi Engineering & QA Ecosystem

krocker-compose is an internal developer CLI tool built to solve local orchestration friction for complex, microservice-based conversational Natural Language Understanding (NLU) platforms.

Background & The Problem

At TiVo, conversational NLU pipelines consisted of dozens of interconnected services: dialogue management, entity extractors, semantic parsers, domain deciders, and knowledge graph indices.

Previously, running services locally for feature testing or QA verification required spinning up heavy monolithic EC2 instances or manually configuring dozens of environment variables, port mappings, and mock model weights. This slowed down developer feedback loops and bloated infrastructure costs.

The Solution

krocker-compose abstracted the container orchestration into a declarative, single-command developer experience. Engineers could compose and spin up arbitrary topologies of services matching specific testing scenarios:

  • Profile-driven topology generation: Allowed developers to declare profiles (e.g. sports-domain, movie-discovery, or full-e2e) which synthesized optimal docker-compose manifests on the fly.
  • Dynamic port & volume mapping: Handled model artifact caching and dynamic host port bindings to eliminate port collision across concurrent feature branches.
  • Hot-reloading & local override: Let engineers mount local source trees into running containers with one flag, enabling sub-second code iteration cycles without rebuilding images.

Impact

Reduced developer onboarding and local environment bootstrap time from half a day to under two minutes, while enabling QA to run isolated regression suites locally without incurring cloud EC2 costs.
